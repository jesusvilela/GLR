# GLR x Spin Woven Numbers | R1 Teloi + two-pass experiment

**Independent fork experiment. Idiap's original code, paper citation and baseline are untouched.**

At R1 we choose **Teloi-governed second-pass revision** over changing Qwen3's backward attention or introducing trainable associative layers. All changes are opt-in. The second pass is *another causal inference run*, not bidirectional attention and not the original paper's two-forward-pass **training** procedure.

## Mathematical interface

Idiap GLR (trained with the additive transition-head option) uses

    e_(t+1) = e_t + delta_t
    delta_t = W h_t + b.

The R0 spinor-block proposal replaces only the predicted delta, using the explicitly chosen S3 spinor matrices s,t from Spin Woven Numbers:

    C = st - ts
    G = (1 / |S3|) sum_g rho(g)^T rho(g)        # auxiliary SPD metric
    q(x) = x^T G x
    F_eps(x) = x + eps * q(x)/(1+q(x)) * Cx.

The learned Qwen embedding space is NOT a canonical Clifford representation. Four-channel blocks and their ordering are chosen, unproven coordinates; a coordinate permutation negative control is needed before claiming geometric structure. Only the explicit R0 frame-change test, which transports BOTH the operators and the metric, is covariant.

## Telos / Teloi

In SWN-9, singular **Telos** means a feasibility contract; plural **Teloi** means a family of objectives with a Pareto partial order. R1 uses this distinction in two places:

1. Runtime Telos gate: reject a nonfinite candidate or an excessively large perturbation relative to the original learned GLR delta. Restore the source delta and count a **typed remainder**; if the original delta itself is nonfinite, evaluation must stop rather than claiming success.
2. Post-hoc Teloi evaluation: GSM8K exact-match accuracy (maximize), generated steps including both passes (minimize), elapsed wall time (minimize), and fallbacks per example (minimize). **No scalarization.** A trade-off is *incomparable*, not an automatic improvement.

The runtime Telos has **no access to test-set gold answers**. The post-hoc reporter uses gold only after predictions have been written.

## Arms / nonconfounded comparisons

| Arm | Latent delta | Inference passes |
|---|---|---:|
| glr | unmodified | 1 |
| swn | SWN noncommutative update | 1 |
| random | deterministic random skew mixer with per-block matched perturbation norm | 1 |
| glr_2pass | unmodified | 2 |
| swn_2pass | SWN update | 2 |
| random_2pass | random control | 2 |

Two-pass inference: the first draft is generated by GLR; a *new forward causal prompt* presents the original question and the draft as fallible text, asks for independent checking and emits a revised answer. The runner **always uses the second answer**: it does not choose by test-set correctness. Both GLR and SWN have equal two-pass opportunities and per-pass generation budgets.

A two-pass arm costs additional tokens/compute; comparisons against one-pass controls without accounting for this are not evidence of a SWN benefit.

## Preregistered first pass

- Model: **trained** GLR Qwen3-0.6B, NOT Qwen3-0.6B pretrained base alone.
- K=10 learned latent steps, epsilon=0.02, fixed seed=2026.
- Initial GSM8K 10-example smoke, then a *frozen* untouched subset and finally the complete GSM8K evaluation set when compute permits.
- Maximum 512 generated steps **per pass**. Two-pass arms can use up to 1024, reported explicitly.
- Compare SWN against same-pass GLR AND same-pass norm-matched random mixing.
- Measure paired correctness changes with a bootstrap interval (descriptive at tiny N); inspect exact output and large numerical reversion events.
- **Kill conditions:** an invalid base checkpoint; numerical instability; no gain over control within the same pass budget; improvement attributable only to a second pass or coordinate-dependent arbitrary mixing.

## Run

Install the upstream pinned environment in the official README; no modifications to upstream dependencies are needed. First train or otherwise obtain a legitimate GLR checkpoint containing both learned Qwen and learned direction-head parameters.

    python -m unittest discover -s tests -p test_swn_r1.py -v

    python -m experiments.swn_r1.run \
      --checkpoint /path/to/TRAINED/glr_qwen3-0.6B \
      --eval-file /path/to/gsm8k_zeroshot.jsonl \
      --output /tmp/glr_swn_r1.jsonl \
      --max-examples 10 --K 10 --strength 0.02 \
      --max-new-tokens 512 --seed 2026

    python -m experiments.swn_r1.score \
      --predictions /tmp/glr_swn_r1.jsonl \
      --summary /tmp/glr_swn_r1_summary.json

Each result contains the complete generated response for the chosen arm, first-pass draft for two-pass arms, per-pass token counts, wall time, Telos reversion counts and bounded diagnostics.

## Actual evidence status

- **P (source math only):** finite S3 generator relations and corresponding concrete spinor matrices appear in SWN's Lean files, subject to that project's exact proof artifact. R1 does not prove a representation theorem for Qwen.
- **M:** R0 operator structural tests ran; R1 structural tests must pass for the actual commit/environment before labeling R1 integration verified.
- **H:** SWN nonlinear deltas and return-pass revision improve held-out mathematical correctness at matched resources.
- **R / excluded:** trained GLR weights are NOT shipped in this GitHub repository; no inference, benchmark result, or improved capability is implied by committing this harness.
